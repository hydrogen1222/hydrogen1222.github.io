# Quality Gate

最终交付前必须通过以下检查。

## 1. 信息完整度

若用户没有要求摘要：
- 主要技术结论不能凭空消失；
- 关键公式、参数、数量级、文献结论和限定条件应保留；
- 删除内容主要应是重复、口头填充和明显无关支线。

如果整理后篇幅骤减到原稿的一小部分，应主动检查是否误做成了摘要。

## 2. 论证完整度

文章至少应能回答：
- 我们在讨论什么问题？
- 为什么这个问题值得讨论？
- 关键概念为什么在这里出现？
- 不同证据之间是什么关系？
- 最终我们到底能得出多强的结论？
- 哪些地方还不能确定？

## 3. 严谨性

禁止：
- 编造 citation；
- 编造论文结论；
- 编造数值；
- 把相关性写成因果；
- 把单体系观察泛化成普遍规律；
- 把猜测升级为事实；
- 静默修正可能影响结论的公式/单位错误。

## 4. Markdown 可读性

- 标题层级不要跳跃；
- 数学公式保持可渲染；
- Obsidian wikilink 保持合法；
- 避免无意义粗体泛滥；
- 不把连续正文拆成碎片卡片；
- 不为了“美观”引入大量 callout，除非源笔记已有或用户要求。

## 5. 人味

文章允许有：
- “我为什么会困惑”；
- “这里其实有点反直觉”；
- “后来才发现问题出在……”；
- 适量 emoji；
- 轻微幽默。

但这些不能抢走技术内容本身。

## 6. 最后一道测试

分别做三次快速阅读：

### 只看正文
不看标题也应该能顺畅理解。

### 只看技术细节
数字、公式、定义、单位、限定条件应该彼此一致。

### 回看源笔记
重要信息不能因为“写得更顺”而被悄悄抹掉。

三项都过，才交付。
