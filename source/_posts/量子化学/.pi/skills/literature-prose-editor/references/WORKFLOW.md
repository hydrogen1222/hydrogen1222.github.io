# Workflow — 从杂乱笔记到可读文章

## A. 确定范围

先从用户明确给出的文件或目录开始。

若是目录级任务：
1. 列出候选 Markdown 文件；
2. 根据文件名、链接关系和内容检索判断相关性；
3. 只读取与主题真正相关的材料；
4. 不要因为“可能相关”就把整个 Vault 全吞进上下文。

如果用户指明某些笔记是核心材料，以它们为主；其他笔记只用于补充与交叉检查。

## B. 完整阅读，而不是片段拼接

对于最终会被写进文章的关键笔记，应尽量完整阅读。

内部建立一个 evidence map，至少区分：

- **事实/定义**
- **公式**
- **数值/参数**
- **文献结论**
- **作者自己的观察**
- **作者自己的疑问**
- **推测**
- **冲突**
- **重复**

evidence map 是内部工作材料，不必输出给用户。

## C. 找出真正的中心问题

不要把“文件夹名”自动当成文章主线。

例如一堆恒温器笔记的中心问题可能不是：

> “有哪些恒温器？”

而是：

> “如果目标是 Li 离子扩散，控温算法到底会不会污染动力学？”

后一种问题更容易形成自然文章。

若材料里存在多个同等级问题，可以分成少数 H2，而不是塞进一个大杂烩章节。

## D. 重新排序信息

优先使用逻辑顺序，而非记录顺序。

常用关系：

- 因果；
- 前提 → 结论；
- 现象 → 解释；
- 常见直觉 → 反例；
- 方法 A → 方法 B 的差异；
- 理论 → 文献证据 → 自己的数据；
- 已知 → 未知；
- 争议双方 → 分歧究竟在哪个假设。

文献名称不应该天然成为一级组织单元。

## E. 处理重复

重复内容分三类：

1. **完全重复**：保留更完整/更准确的一处。
2. **同义但角度不同**：融合成一段，保留有价值的不同视角。
3. **看似重复但限定不同**：不能合并掉限定条件。

不要为了“去重”把重要 caveat 删除。

## F. 处理冲突

发现冲突时：

- 若只是符号不同：统一符号，并说明原定义差异（必要时）。
- 若数值不同：检查单位、温度、拟合窗口、定义等上下文。
- 若仍无法解释：明确写出冲突，提醒回查原文。
- 不要偷偷挑一个“看起来合理”的答案。

## G. 草拟叙事骨架

内部只需 3–7 个大节点。

示例：

1. 为什么“控温正常”还不够；
2. thermostat 改变了什么；
3. 为什么平衡分布与动力学是两回事；
4. 几类 thermostat 的差别；
5. 文献到底测到了什么；
6. 回到自己的扩散计算应该怎么判断。

不要把这个内部骨架直接作为最终提纲输出。

## H. 写第一稿

写作时遵循：

- 每段解决一个问题；
- 概念出现前给出动机；
- 公式出现后解释其当前意义；
- 文献不是“插入 citation”，而是承担证据角色；
- 用户自己的观察尽量融入论证；
- 允许少量“我当时为什么会困惑”的个人线索。

## I. Fidelity Pass

逐项回查：

- [ ] 数字是否一致；
- [ ] 单位是否一致；
- [ ] 公式是否遗漏项；
- [ ] 正负号、上下标是否正确；
- [ ] 温度/压力/时间尺度是否混淆；
- [ ] 文献结论是否被夸大；
- [ ] 原笔记的“可能/推测”是否被写成确定事实；
- [ ] citation / DOI / wikilink 是否仍支持旁边的论断；
- [ ] 是否删除了有价值的反例或 caveat；
- [ ] 用户自己的结果是否和文献结果混写。

## J. Style Pass

检查：

- [ ] 是否仍然像提纲；
- [ ] 标题是否过多；
- [ ] bullet 是否能改回自然段；
- [ ] 是否有连续的“首先/其次/此外”；
- [ ] 是否存在模板化“概述—优点—缺点—总结”；
- [ ] 段落之间是否有自然逻辑；
- [ ] 是否过度压缩；
- [ ] 是否加入了源笔记没有的装腔术语；
- [ ] emoji 是否自然且克制；
- [ ] 不看标题时正文是否仍然连贯。

## K. 输出

默认不覆盖源文件。

若是单篇：
`foo.md` → `foo.prose.md`

若是多篇：
创建主题明确的新文件，例如：
`恒温器、动力学与离子扩散.md`

若用户已指定目标文件，则使用目标文件。

完成后只简短报告：
- 写到了哪里；
- 有无冲突/疑似错误；
- 哪几处值得人工回查。
